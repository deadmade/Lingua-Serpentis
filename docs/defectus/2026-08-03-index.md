# Lingua Serpentis — Defect Register

Opened 2026-08-03 by the conformance and robustness suite
(`docs/superpowers/specs/2026-08-03-conformance-and-robustness-suite-design.md`).

**Status, 2026-09-15: 27 of the 30 are fixed; 2 are deferred; 1 is open.**
D-30 sits after Appendix C rather than with the numbered run. The
plan for D-01…D-25 is
`docs/superpowers/plans/2026-08-05-defect-register-remediation.md`.

**D-28 and D-29 are the compiler-backend milestone's whole-branch review**, and
both live where no per-task brief could look: D-28 at the seam between two crates
each reviewed on its own terms, D-29 on a build path no task exercised. Both were
recorded, not fixed, and each named its close. Both were fixed on 2026-09-15 —
D-29 by the close it named, D-28 by a narrower one, recorded in its entry.

**Task 19 of the compiler-backend milestone deleted the interpreter**
(spec §3.1), and four entries move with it:

- **D-19 is closed.** Its stated blocker was that the 62 unit tests on the laxer
  legacy API were "a test rewrite, not a fix". The rewrite is done: `parse`,
  `check` and `interp::execute` are gone, and every test that drove them now
  goes through `parse_file` / `check_program` under a `munus initium` wrapper.
  The two things the entry named as depending on it went with them —
  `'redde' extra functionem` is deleted and `current_ret` is no longer an
  `Option`; `Checker::new`'s permissive namespace default is a parameter.
- **D-04 is superseded**, not re-opened. The defect (unbounded recursion leaving
  the error model) is still fixed, but by a different mechanism saying a
  different sentence. See its entry.
- **D-06's fix has relocated into the runtime.** Same behaviour, different
  process. See its entry.
- **D-26 has only one side left**, so it stops being a divergence between two
  implementations and becomes a plain language question — since answered: a
  `dum` init clause is a declaration or an assignment. See its entry.

**D-26 and D-27 are new**, and neither came from §8.1: both surfaced during the
compiler-backend milestone (`docs/superpowers/plans/2026-08-07-compiler-backend.md`,
Task 13), which is the first thing in the project to execute the language twice
and compare. D-27 is fixed. **D-26 was the register's first entry that is not a
bug in one implementation but a disagreement between two**, and was fixed on
2026-09-15 by a grammar rule for the `dum` init clause.

Each fixed defect's `conformance/defectus/` fixture has moved to `errores/`,
`currunt/` or `monita/` with the corrected expectation, and its `NOTA.md`
rewritten to say what the behaviour was and what it is now. Those notes are
where the per-defect story lives; the entries below are preserved as the
record of the defect **as found**, not as a description of today's code.
`conformance/defectus/` holds one directory, D-13's, which is deferred.

`RECORDED_RULES` (`crates/lingua-serpentis/tests/support/diag.rs`) went from
six entries to one. Only `terminates` remains, held open by the deferred D-20.
No rule was weakened to get there. `cargo test -- --ignored` now reports
nothing: both aspirational tests, D-04's and D-06's, are ordinary passing
tests.

It is still one entry after Task 19, and `judge` has **gained three rules**
without `RECORDED_RULES` growing — the two are opposites. A `RECORDED_RULES`
entry is a violation the suite tolerates; a new rule is a violation it refuses.

- `no abort`, keyed on `Error: programma abrupte cessavit` — what a killed child
  looks like from outside `liss run`, and the only fuzzed enforcement spec §8
  has, because the process the harness spawns is the compiling parent and that
  one does not die by signal.
- `no internal defect`, keyed on the prefix `defectus internus: ` — the compiler
  admitting to a bug, which is what both fuzzers exist to find. Task 12's
  Critical had exactly this shape: the legal program `redde nullus;
  scribe("numquam");` made release codegen say `munus componi non potuit`, and
  `judge` would have called it Acceptable.
- `no leak`, keyed on `Error: memoria non liberata est` (spec §7.5).

All three sentences are well-formed structural Latin carrying no file, no line,
no English word, no Arabic digit and no Rust type name, so every lexical rule
passed them. **They are violations for what they report, not for how they read.**
None fires on anything today: the corpus, the eleven curated pathologies and
3,000 mutation draws are clean.

The two deferred defects are language changes the suite design's §2 lists as
Non-Goals, and each needs its own spec before it can be scheduled. (D-26 was the
third, and closed with its own spec, `2026-09-15-dum-header-clause-design.md`.)

| ID | why it is deferred |
|----|--------------------|
| D-13 | Validating Roman numeral form is a breaking change to every non-canonical literal, and needs a spec deciding canonical form, subtractive pairs and repetition limits. |
| D-20 | `x = x * x` does not terminate because `Roman` is arbitrary-precision. A magnitude cap is a new language limit with a new diagnostic. |

### D-01 · Nulla analysis reditus — the type system is unsound

- **Severity:** high — a checker-approved program produces a value of the wrong type
- **Repro:** `conformance/defectus/D-01-reditus-omissus/`
- **Observed:** `munus nomen reddit voc { si (falsus) { redde "a"; } }` called from
  `initium` prints `nullus` on stdout, empty stderr, exit 0 — a declared-`voc`
  call yielded an `Int`.
- **Expected:** a checker error naming the missing return.
- **Cause:** `interp.rs:168` ends every call body with `Ok(Value::Int(Roman::zero()))`
  regardless of the declared return type; `checker.rs:412` only type-checks the
  `redde` statements actually written and never asks whether one is reachable on
  every path.
- **Note:** this is what promotes the "defensive" interpreter messages from
  unreachable to reachable. Both were confirmed by hand:
  `scribe(nomen() + "b")` gives
  `Error in 'principale.liss', linea 8: operatio binaria invalida`, and
  `si (vera())` on a `reddit veritas` function with no reachable `redde` gives
  `Error in 'principale.liss', linea 8: condicio non est veritas`.
  `comparatio invalida` (`interp.rs:358`) and `subscriptio invalida`
  (`interp.rs:136`) are reachable by the same route.
  Any fix must special-case `initium`, whose fall-through the packages design
  licenses deliberately and which `interp.rs:609::falling_off_initium_exits_zero`
  pins as correct.

### D-02 · `expectatum: Semicolon` — a Rust type name in a Latin diagnostic

- **Severity:** medium — user-facing text is coupled to a private Rust enum
- **Repro:** `conformance/errores/expectatum-semicolon/`
- **Observed:** a missing `;` gives
  `Error in 'principale.liss', linea 3: expectatum: Semicolon`, exit 1.
- **Expected:** the Latin name of the missing token, e.g. `expectatum: ';'`.
- **Cause:** `parser.rs:28` — `Err(self.err(&format!("expectatum: {:?}", kind)))`
  formats a `TokenKind` with `Debug`. There are 29 `self.eat(...)` call sites
  reaching it, over exactly **7** distinct variants: `Assign`, `LBrace`,
  `LParen`, `RBrace`, `RBracket`, `RParen`, `Semicolon`. Renaming any one of
  those variants silently changes user-facing text.
- **Note:** the fixture also pins that the reported line is 3, not 2 — the
  parser reports at the token *following* the missing semicolon.

### D-03 · Line numbers are wrong after a multi-line string

- **Severity:** high — every diagnostic and warning after a multi-line string
  points at the wrong source line
- **Repro:** `conformance/defectus/D-03-linea-post-chordam/`
- **Observed:** a string literal spanning source lines 2-3, then an undefined
  variable on source line 5, gives
  `Error in 'principale.liss', linea 4: variabilis ignota: 'ignota'`, exit 1.
- **Expected:** the same message with `linea 5`. The drift is one line per
  embedded newline, and is unbounded.
- **Cause:** `lexer.rs:46` — the string body is scanned with
  `while i < chars.len() && chars[i] != '"' { i += 1; }`, which walks over `\n`
  without incrementing `line`. Every token emitted afterwards carries the
  understated number, so `Monitum in ..., linea N` drifts identically.

### D-04 · Unbounded recursion aborts the process

- **Severity:** high — the failure is outside the error model entirely; an
  embedder cannot survive it
- **Repro:** `munus recurre capit (ni n) reddit ni { redde recurre(n + °I); }`
  called from `initium`. Not fixture-shaped: `SIGABRT` kills the test process
  and `catch_unwind` does not catch it, so this needs a subprocess.
- **Covered by:** `crates/lingua-serpentis/tests/cli.rs` (as an `#[ignore]`d
  test) and the `robustness.rs` `no abort` invariant with a D-04 allowlist entry.
- **Observed:** stdout empty; stderr
  `\nthread 'main' (<pid>) has overflowed its stack\nfatal runtime error: stack overflow, aborting`;
  exit **134** (128 + SIGABRT).
- **Expected:** a Latin diagnostic and exit 1, or a documented recursion limit.
- **Cause:** `interp.rs:142` — `Interp::call` recurses through
  `exec` → `eval` (`interp.rs:83`, the `Expr::Call` arm) → `call` with no depth
  counter and no growable stack.

#### Superseded 2026-08-08 — the mechanism and the wording both changed

The defect is still fixed: unbounded recursion is still an ordinary exit-1 Latin
diagnostic and never a signal. But nothing of the original fix survives.

| | fix as recorded above | as of Task 19 |
|---|---|---|
| mechanism | `VOCATIONES_MAXIMAE = 64`, a counter in `Interp::call` | a `SIGSEGV` handler on an alternate stack (spec §8) |
| when it fires | the 65th frame | the guard page, ~40,000–80,000 frames down |
| sentence | `vocatio nimis alte implicata` | `acervus vocationum exhaustus est` |
| line number | the call's own | none — §8.4, a handler has no line table |
| fixture | `errores/vocatio-nimis-alte-implicata` | `errores/acervus-exhaustus` |

**The cap was never a language decision.** It existed because a tree-walker
spends many Rust frames per Lingua Serpentis frame, and 64 was half the measured
ceiling on a 2 MiB spawned-thread stack. Spec §3.3 removes it with the
interpreter that motivated it, and the two sentences are not synonyms: one means
"the interpreter refused to go deeper", the other "the machine ran out of
stack". Only the second is a fact about the language.

The `no abort` rule that this defect and D-05 shared stays retired, and it is
now enforced *twice*: `judge` treats a signalled process as a violation, and —
since the process the harness spawns is the compiling parent, which does not die
by signal — it also treats `Error: programma abrupte cessavit` as one, that being
the only form in which a killed child can reach it (spec §9.5).

Two new fixtures guard the replacement from the other side.
`currunt/recursio-profunda` runs 5,000 levels and must **not** raise, so a guard
that fired early would be caught; `currunt/scribe-ante-acervum` pins that output
buffered before the fault still reaches stdout, which is D-08's obligation
discharged inside a signal handler.

### D-05 · Deep expression nesting aborts in the parser

- **Severity:** medium — a malformed or machine-generated source file aborts
  the process instead of producing a diagnostic
- **Repro:** `ni x = ((((…°I…))));` with 2000 or more nested parentheses. Not
  fixture-shaped for the same reason as D-04.
- **Covered by:** the `robustness.rs` nesting-depth pathology sweep with a D-05
  allowlist entry against the `no abort` invariant.
- **Observed:** measured in the debug build on 2026-08-03: 1000 nested
  parentheses → exit 0, clean; **2000** → exit 134 with
  `fatal runtime error: stack overflow, aborting`. 4000, 8000 and 20000 behave
  the same as 2000.
- **Expected:** a Latin diagnostic and exit 1, or a documented nesting limit.
- **Cause:** `parser.rs:143` — `primary`'s `LParen` arm calls `self.expr()`, so
  the whole recursive-descent chain `expr → or_expr → … → unary → primary`
  re-enters once per parenthesis, with no depth counter.
- **Note:** the design's §8.1 estimate of "~20k nested parens" is an order of
  magnitude too generous for the debug build; see Appendix A.

### D-06 · A broken pipe panics

- **Severity:** medium — the most ordinary shell idiom (`prog | head`) produces
  a Rust panic message and a non-standard exit status
- **Repro:** a program printing many lines, piped into `head -1`. Not
  fixture-shaped: the library never touches a pipe, only `main.rs` does.
- **Covered by:** `crates/lingua-serpentis/tests/cli.rs` (as an `#[ignore]`d
  test) and the `robustness.rs` `no panic` invariant with a D-06 allowlist entry.
- **Observed:** one line of correct output, then on stderr
  `thread 'main' (<pid>) panicked at …/std/src/io/stdio.rs:1166:9:` /
  `failed printing to stdout: Broken pipe (os error 32)` /
  `note: run with RUST_BACKTRACE=1 …`; exit **101**.
- **Expected:** silent termination on `EPIPE`, the way every Unix tool behaves.
- **Cause:** `main.rs:9` — `print!("{}", r.stdout)` panics on a write error
  because Rust's runtime sets `SIGPIPE` to `SIG_IGN`. `main.rs:8`'s `eprint!`
  has the same exposure on stderr.

#### Relocated into the runtime 2026-08-08 — same behaviour, different process

The fix is unchanged in what a user sees and has moved to where the writing now
happens. `main.rs` is deleted; the compiled program, not the CLI, is what holds
the pipe.

`liss run` spawns the image with **inherited** stdio (spec §9.5), so the closed
pipe is delivered to the child. Two pieces of `abi` take it from there:
`custos.rs` sets `SIGPIPE` to `SIG_IGN` — necessary because `std::rt::init`
never runs under a `#[unsafe(no_mangle)] extern "C" fn main`, so the runtime does
not inherit std's disposition and the default would kill the child outright —
and `scriptio::scribe_ad` treats the `EPIPE` that then surfaces as an ordinary
end of output and exits 0. Without the first, the second is unreachable code.

`cli::write_or_exit` keeps the same handling for the parent's own stream, which
still matters: the parent writes Latinity warnings to stderr before it spawns.

`tests/cli.rs::a_closed_pipe_is_not_a_panic` is the same test it was, now
pointed at `liss`. It reads a little of the child's stdout, closes the pipe, and
requires that nothing panics and nothing exits 101 — which now exercises the
runtime's disposition rather than the CLI's.

### D-07 · `abrumpe` extra iterationem tacite ignoratur

- **Severity:** medium — silently wrong behaviour, no diagnostic
- **Repro:** `conformance/defectus/D-07-abrumpe-extra-iterationem/`
- **Observed:** `scribe(°I); abrumpe; scribe(°II);` directly in `initium` prints
  `I` then `II`; stderr empty; exit 0. `continua` in the same position is
  identical.
- **Expected:** an error naming `abrumpe` outside a loop.
- **Cause:** `checker.rs:449` — `StmtKind::Break | StmtKind::Continue => Ok(())`,
  with no loop-depth tracking anywhere in the checker; `interp.rs:225` yields
  `Flow::Break`, and the function-body loop at `interp.rs:166` matches only
  `Flow::Return`, so the `Break` is dropped on the floor.

### D-08 · A runtime error discards everything already printed

- **Severity:** high — output the program provably produced is thrown away
- **Repro:** `conformance/defectus/D-08-emissio-perdita/`
- **Observed:** `scribe("ante")` followed by a division by zero gives **empty**
  stdout, stderr `Error in 'principale.liss', linea 4: divisio per nullum`,
  exit 1.
- **Expected:** stdout `ante`, then the error on stderr.
- **Cause:** `interp.rs` accumulates `scribe` output in `Interp::out`;
  `execute_program` (`interp.rs:390`) returns it only in the `Ok` arm, and
  `run_loaded`'s `?` at `lib.rs:44` discards it. `render` (`lib.rs:121`) then
  emits an empty stdout for any `Err`.

### D-09 · Any error discards all Latinity warnings

- **Severity:** medium — a diagnostic the linter produced is computed and thrown
  away, so a program with two problems only ever reports one
- **Repro:** `conformance/defectus/D-09-monita-perdita/`
- **Observed:** a program with the non-Latin name `counter` **and** a division by
  zero gives stderr containing only
  `Error in 'principale.liss', linea 4: divisio per nullum`, exit 1. Remove the
  division and the same program emits
  `Monitum in 'principale.liss', linea 2: nomen 'counter' fortasse non Latinum est`
  — so the warning exists and is discarded.
- **Expected:** the `Monitum` line, then the error.
- **Cause:** `lib.rs:43` computes `warnings`; `run_loaded` returns them only on
  the `Ok` arm at `lib.rs:45`. The `?` on `lib.rs:44` (interpreter) and the `?`
  on `lib.rs:42` (checker) both drop them.

### D-10 · The exit status is silently truncated

- **Severity:** low — Unix-correct but undiagnosed; a program's own status can
  become 0
- **Repro:** `munus initium reddit ni { redde °CCC; }`. Not fixture-shaped: the
  library's `run_with_warnings` discards the `u8` (`lib.rs:88`), so only a
  subprocess observes the real status.
- **Covered by:** `crates/lingua-serpentis/tests/cli.rs`.
- **Observed:** `redde °CCC` (300) → exit **44**; `redde nullus - °I` (-1) →
  exit **255**; `redde °CCLVI` (256) → exit **0**. No warning in any case.
- **Expected:** at minimum a `Monitum` when the returned `ni` does not fit in
  0..=255.
- **Cause:** `interp.rs:381` — `exit_status` reduces mod 256 and shifts a
  negative remainder up by one modulus. The behaviour is deliberate and
  documented in the doc comment above it; what is missing is any signal to the
  user that it happened.

### D-11 · Two English diagnostics in `main.rs`

- **Severity:** low — but it is the one rule the language has: every message the
  user sees is Latin
- **Repro:** `lingua-serpentis notae.txt` and `lingua-serpentis absens.liss`.
  Not fixture-shaped: both sites are in `main.rs`, which the in-process runner
  never enters.
- **Covered by:** `crates/lingua-serpentis/tests/cli.rs` and the
  `robustness.rs` `Latin only` invariant with a D-11 allowlist entry.
- **Observed:**
  - a path not ending in `.liss` → `Error: file must have .liss extension`, exit 1;
  - a missing file → `Error reading file: No such file or directory (os error 2)`,
    exit 1.
  Both sit one line below the correctly-Latin
  `Usus: lingua-serpentis <via.liss | directorium>` (`main.rs:16`).
- **Expected:** Latin, in the `Error: …` shape the rest of the language uses.
- **Cause:** `main.rs:24` and `main.rs:29`.
- **Note:** the second message is also *wrong* for a directory argument that
  does not exist. A nonexistent `directorium/` fails `is_dir()`, falls through
  the extension check and reports `Error: file must have .liss extension` — the
  first message, misapplied. A nonexistent `directorium.liss/` reports
  `Error reading file: …` — the second message, calling a directory a file.
  The design's §8.1 attributes the misfire only to the second; both misfire.

### D-13 · Roman numeral form is never validated

- **Severity:** medium — the language's central literal accepts non-numerals
- **Repro:** `conformance/defectus/D-13-numerus-non-canonicus/`
- **Observed:** `scribe(°IIX + °VV + °IM);` prints `MXIX`, exit 0. Individually:
  `°IIX` → `X` (10), `°VV` → `X` (10), `°IM` → `CMXCIX` (999).
- **Expected:** `numerus Romanus invalidus` for each.

### D-19 · 62 unit tests run against the laxer legacy API

- **Severity:** medium — the largest block of tests in the workspace certifies a
  language the compiler does not implement
- **Repro:** none — this is a property of the test suite, not of a program.
- **Covered by:** this register only. The conformance suite design's §2
  explicitly declines to resolve it ("No rewrite of the existing 242 tests").
- **Observed:** counted on 2026-08-03 by splitting each file on `#[test]`:
  `parser.rs` 17 of 33, `checker.rs` 29 of 40, `interp.rs` 16 of 30 — **62** of
  103 — drive `parser::parse` / `checker::check` / `interp::execute` through the
  test helpers `parse_all` / `parse_err` (`parser.rs:465`, `parser.rs:469`),
  `check_src` (`checker.rs:640`) and `run` (`interp.rs:434`). Typical bodies are
  `check_src("ni x = °V; x = x + °I; scribe(x);")` and
  `run("scribe(°V + °III * °II);")` — neither is a legal program.
- **Expected:** the unit tests exercise the same language the binary does, or
  the legacy entry points are removed.
- **Cause:** three parallel entry points that are strictly laxer than the
  program pipeline:
  - `parser::parse` (`parser.rs:409`) loops `statement()` over every token, so
    top-level statements are legal; `parse_file` (`parser.rs:420`) allows only
    `affer` lines followed by `munus` declarations.
  - `checker::check` (`checker.rs:519`) registers functions with a plain
    `insert` and has **no** duplicate check; `collect_sigs` (`checker.rs:553`)
    raises `functio '{}' bis definita`. `check` also has no `initium`
    requirement; `check_program` (`checker.rs:599`) raises
    `munus 'initium' in programmate non inventum`.
  - `interp::execute` (`interp.rs:363`) executes top-level statements directly
    and never looks for `initium`; `execute_program` (`interp.rs:390`) calls it
    as the entry point.
- **Note:** the design's §8.1 says "~50"; the measured figure is 62. See
  Appendix A.

#### Closed 2026-08-08 — the rewrite happened

The entry deferred itself on the grounds that this was "a test rewrite, not a
fix". Spec §3.1 scheduled that rewrite as the price of deleting the interpreter,
and Task 19 performed it. All three laxer entry points are gone —
`parser::parse`, `checker::check`, `interp::execute` — and with them the shadow
language that accepted top-level statements, `initium`-less scripts and
duplicate function names.

**The tests were wrapped, not dropped.** What they were *about* — precedence,
scopes, conditions, list element rules, parse errors — is language behaviour
that still exists, so each source is now the body of a `munus initium`:

| file | tests | how |
|---|---|---|
| `parser.rs` | 35 | `parse_stmts` wraps and returns the body; `parse_all`, `parse_err` and `parse_first_expr` are unchanged above it |
| `checker.rs` | 48 | `check_src` wraps and calls `check_program`; the 8 sources that declare their own functions call `check_totum` and write their own `initium` |
| `latinity.rs` | — | `lint_src` wraps and lints the body only |

The wrapper is one line, so every asserted line number is unchanged, and the
body it creates is the root `initium` — the one function permitted to fall off
its end (§4.3) — so a statement sequence with no `redde` still checks.

`interp.rs`'s own 30 tests could not be wrapped, because the thing they tested
is what was deleted. Task 4 ported ~20 of them to `conformance/` fixtures
**while the interpreter still existed**, which was the whole reason for doing it
then; the rest are covered by `codegen`'s per-operator tests and the corpus.

**Two things this entry named as blocked by it are gone with it**, and both were
removed structurally rather than left as `unreachable!`:

- `checker.rs`'s `'redde' extra functionem` was reachable only through `check`,
  which could be handed a top-level `redde`. `current_ret` is a `Type` now, not
  an `Option`, so the state that raised it cannot be built. `check_file`'s
  unreachable non-`Func` fallback — the last path that could have bypassed
  `check_func_decl` — went too, which is what makes the type change sound.
- `Checker::new`'s permissive namespace default is a **parameter**. `None` means
  the program's root, and the root's `initium` is the entry point exempt from
  the all-paths-return rule; a default that quietly said "root" handed that
  exemption to whoever forgot to set the field.

### D-21 · `mag_divmod`'s zero guard is a `debug_assert`

- **Severity:** low — unreachable today, and a latent release-only hang if any
  future caller stops guarding
- **Repro:** none reachable from source. Recorded for the invariant, not for a
  test.
- **Covered by:** this register only.
- **Observed:** every caller guards. `interp.rs:317` and `interp.rs:330` reject
  a zero divisor with `divisio per nullum` / `modulus per nullum` before
  reaching `div_rem`; `fraction::div` (`fraction.rs:31`) returns `None` on a
  zero divisor; `fraction::from_rational` and `fraction::mul` divide only by a
  constant grain; `exit_status` divides only by 256.

  A zero *denominator* in a fraction literal also never reaches a division, but
  **not** by the route first recorded here. The probes `°I:I/N`, `°I:I/` and
  `°I:I/O` all fail with `numerus Romanus vacuus` or
  `numerus Romanus invalidus`, which is `convert_single` (`roman.rs:193` and
  `roman.rs:205`). None of them reaches `roman.rs:252`'s `den.is_zero()` check.
  The conclusion holds — nothing divides — but the guard doing the work is
  `convert_single`, not `denominator est nullus`.
- **Also worth knowing: `roman.rs:253` looks like dead code.** For
  `den.is_zero()` to be true, `convert_int_roman` would have to return zero, and
  it appears it cannot: `convert_single` was evaluated over all 960,799 strings
  of length 1..7 over `I V X L C D M` and returned neither zero nor a negative
  (minimum 1). `convert_int_roman` then only multiplies and adds those, so its
  result is always ≥ 1. The one test that looks like it covers the branch,
  `roman.rs:446::parse_rejects_malformed_or_zero_fraction`, asserts only
  `is_err()`; run directly, `parse_roman("°V:I/nullus")` returns
  `Err("numerus Romanus invalidus: 'nullus'")`, so it passes through
  `roman.rs:205` and never exercises `roman.rs:253`. If the catalogue ratchet
  (design §7) classifies this site, `DEAD` is the honest label.
- **Expected:** a real guard, since `Roman::div_rem` (`roman.rs:336`) is `pub`.
- **Cause:** `roman.rs:110` —
  `debug_assert!(!d.is_empty(), "mag_divmod requires a non-zero divisor")`,
  compiled out in release. With `d` empty, `mag_cmp(n, d)` is `Greater`, so the
  early return is skipped and the doubling loop at `roman.rs:118` computes
  `mag_add(&dd, &dd)` on an empty `dd` forever, doubling `pow` until memory runs
  out.

### D-23 · The Latin identifier checker is quadratic in name length

- **Severity:** low — reachable only with an unusually long identifier, but the
  slowdown is severe and undiagnosed
- **Repro:** `conformance`-external; `crates/lingua-serpentis/tests/robustness.rs`'s
  `nomen longissimum` pathology: a single top-level `ni` declaration whose name
  is 100,000 `a` characters. Not fixture-shaped: the fixture runner has no
  timeout, and the point being demonstrated is that the run exceeds one.
- **Covered by:** `robustness.rs`'s `terminates` invariant (per-input timeout,
  already allowlisted via D-20) with a D-23 allowlist entry in `pathologies()`.
- **Observed:** timed directly against `target/debug/lingua-serpentis` on
  2026-08-03 with an otherwise-trivial program (`munus initium reddit ni { ni
  <name> = °I; redde nullus; }`), name length vs. wall time: 1,000 → 0.31s;
  5,000 → 0.37s; 10,000 → 0.55s; 20,000 → 1.26s; 50,000 → 6.21s; 100,000 →
  24.0s. The run does terminate (exit 0, a `Monitum … fortasse non Latinum est`
  warning) — it is not a hang — but it blows through `robustness.rs`'s 10-second
  per-input deadline somewhere between 50,000 and 100,000 characters, and the
  growth curve (roughly doubling the input roughly quadruples the time from
  20,000 characters on) is quadratic, not linear.
- **Expected:** near-linear time in identifier length, or a length cap with a
  diagnostic.
- **Cause:** `crates/latinitas/src/analyze.rs:31-40` — `analyze`'s loop
  `for i in 0..=w.len() { let (stem, ending) = (&w[..i], &w[i..]); let Some(groups)
  = tables.stems.get(stem) else { continue }; ... }` hashes a `&w[..i]` slice
  against a `HashMap<String, _>` on every one of the `w.len() + 1` iterations.
  Hashing a slice is itself `O(i)`, so the total cost is `O(1 + 2 + … + n)` =
  `O(n²)` in the identifier's length. `latinity.rs:44`'s `check_name` calls
  `latinitas::is_latin` once per declaration site, so this is reachable from
  any single sufficiently long `ni`/`voc`/`munus`/parameter name — no repeated
  use or loop needed.
- **Distinct from D-20.** D-20 is exponential blow-up in `Roman`'s
  representation from repeated squaring in `roman.rs`; this is quadratic
  blow-up in a `HashMap` lookup loop in `latinitas`, triggered by a single
  identifier's length. They share the `terminates` rule because both are
  "eventually finishes, but not within a reasonable bound," not because they
  share a mechanism.

### D-26 · A terminator in a `dum` init clause means two different things

- **Severity:** medium
- **Repro:** `docs/defectus/` has no fixture for this and deliberately so — see
  *Why there is no `conformance/` case* below. Both programs reproduced against
  `target/debug/lingua-serpentis` and against a compiled image on 2026-08-08.
- **Fixed** `a823697`, 2026-09-15 — a `dum` init clause is a declaration
  (`TYPE ident = expr ;`) or an assignment (`ident = expr ;`), decided on
  lookahead in `Parser::for_stmt`, and anything else is rejected at its first
  token with `clausula prima capitis 'dum' declaratio vel assignatio esse debet`.
  That closes the terminator shapes and the `munus`-in-header hole together;
  `regimen.rs`'s `caput_dum_terminatum_componitur` and `generative.rs`'s
  `caput_dum_terminatum` guard were deleted in `3fbc70d`. Spec:
  `docs/superpowers/specs/2026-09-15-dum-header-clause-design.md`.
- **Covered by:** `conformance/errores/{redde,abrumpe,si,munus}-in-capite-dum`
  and `parser.rs`'s `dum_init_is_a_declaration_or_an_assignment`. Until the fix,
  `crates/codegen/tests/regimen.rs`'s `caput_dum_terminatum_componitur` pinned
  the **compiled** behaviour only.
- **Observed.** The parser reads a `dum` init clause with `self.statement()?`
  (`parser.rs:315`) — any statement at all, terminators included — and the
  checker admits one. So this type-checks:

  ```liss
  munus initium reddit ni {
      ni k = nullus;
      dum (redde nullus; verus; k = k + °I) { scribe("numquam"); }
  }
  ```

  | | interpreted | compiled |
  |---|---|---|
  | `dum (redde nullus; …)` above | **never terminates** (killed at 5 s, no output) | exit 0, empty |
  | `dum (abrumpe; …)` in an enclosing loop | the `abrumpe` is **ignored**: `intus intus intus extra extra`, exit 0 | exit 0, empty |
  | `dum (continua; …)` in an enclosing loop | likewise ignored | exit 0, empty |

- **Cause.** `interp.rs:325` is `self.exec(init)?;` — the `Flow` it returns is
  discarded, so `Flow::Return`, `Flow::Break` and `Flow::Continue` from the init
  clause all evaporate and the loop proceeds as though the statement had been a
  `Let`. Compiled code cannot do that: a terminator fills the Cranelift block,
  so codegen must either honour it or crash. It honours it — `redde` returns,
  and `abrumpe`/`continua` bind to the **enclosing** loop, which is the
  checker's own rule for the header ("`init`, `cond` and `step` are the loop's
  header, not its body: an `abrumpe` there is as loose as one outside").
- **Expected.** A language decision, then one behaviour. The three candidates:
  reject a terminator in a `dum` init clause outright (a new diagnostic, and so
  a new language semantic); make the interpreter honour the `Flow`, which makes
  the two agree on codegen's reading; or declare the compiled reading normative
  and change the interpreter, which D-19 will delete anyway.
- **Deferred, and why.** Every candidate is a language change, and "no new
  language semantics" is a stated Non-Goal of the compiler-backend milestone
  (`docs/superpowers/specs/2026-08-07-compiler-backend-design.md` §2). It is
  filed rather than fixed so that it is a decision someone takes rather than one
  the implementation makes by accident.
- **What was done in the meantime.** Codegen was made not to crash. Before
  `9f54f57`, `Corpus::dum_intus` walked the header with no
  terminator guard, so all three programs above were
  `you cannot add an instruction to a block already filled` in debug and
  `defectus internus: munus componi non potuit` in release — a valid program
  told it had broken the compiler. Note that breaking out of the header walk is
  **not** sufficient and was verified not to be: the instruction that lands in
  the filled block is the `jump` that starts the loop, so the whole loop must be
  abandoned.
- **Why there is no `conformance/` case.** The corpus is a *differential*
  corpus: after Task 19 removes the interpreter, Task 17's harness runs every
  case both ways and requires them to agree. These three programs are the first
  in the project that do not agree, so a fixture would encode one backend's
  answer as the language's. **Task 17 must not be surprised by this**, and this
  entry is the notice. When the decision is made, the fixture goes in with it.

#### Revisited 2026-08-08 — one side left, and what that does and does not settle

The interpreter is deleted, so the *disagreement* is over: there is no longer a
second implementation to disagree with. Three consequences, and only the first
is a simplification.

**1. The entry is no longer "a bug in neither implementation".** It was the
register's only such entry. It is now an ordinary open language question with a
single, observable behaviour: `redde` in a `dum` init clause returns, and
`abrumpe`/`continua` there bind to the **enclosing** loop. The
`interp.rs:325` column of the table above is history, kept because it records
what was true when the question was found.

**It remains deferred, and the reason is unchanged.** Nothing about the deletion
decides what the language *should* do; it only removes one of the two answers
that were competing. Two candidates survive, both new language semantics and both
Non-Goals of this milestone (compiler-backend design §2):

- **Reject a terminator in a `dum` init clause** with a new diagnostic. This is
  the more defensible reading — the checker already calls `init`, `cond` and
  `step` "the loop's header, not its body" — and it makes the shape a static
  error rather than something a reader must reason about.
- **Write the compiled reading down as normative.** Costs nothing to implement,
  since it is what happens, but it is still a decision someone has to take
  rather than one the implementation takes by accident. That distinction is the
  whole reason this was filed instead of fixed.

**2. The exclusions that existed to protect the differential are now doing a
different job, and both should stay.** `generative.rs`'s
`caput_dum_terminatum` guard was there so a widened generator could not
synthesise a shape neither backend was wrong about; there is no differential
left for it to break, but it still marks a program whose meaning is undecided,
which is a reason not to generate one. `regimen.rs`'s
`caput_dum_terminatum_componitur` was "codegen's side of it" and is now simply
the pin on the behaviour — the *only* pin, and the thing that would notice a
codegen change silently answering the question.

**3. There is still no fixture, and the argument for that has changed.** It used
to be that a fixture would bless one backend's answer as the language's. Now it
would bless *the* answer as the language's, which is worse: the corpus is what
the compiler is held to, so a fixture here would close the question by
implication, with no spec and no one having decided.

### D-27 · `abolere`'s magic clear is dead-store-eliminated

- **Severity:** medium
- **Repro:** disassemble the shipped runtime object. Found 2026-08-07 while
  mutation-testing Task 13's ownership rules: a mutation that made codegen free
  a `voc` slot *before* reading it produced the right answer and exit 0, where
  the magic check should have reported corruption.
- **Covered by:** `crates/codegen/tests/regimen.rs`'s
  `assignatio_in_ansa_libratur` — which detects the use-after-free only because
  this is fixed.
- **Observed.** `crates/abi/src/memoria.rs`'s `abolere` wrote
  `(*h).magic = 0` immediately before `libc::free`. In the release build — the
  only build that ships, since the musl archive is prebuilt — the store is not
  there. From `runtime.o` as embedded:

  ```
  0000000000000000 <liss_text_free>:
     0:  push   %rax
     1:  test   %rdi,%rdi
     4:  je     22          # null is a no-op
     6:  cmpl   $0x4c495353,(%rdi)
     c:  jne    24
     e:  cmpl   $0x5,0x4(%rdi)
    12:  jne    24
    14:  call   *0x0(%rip)  # free   <- no write to the magic anywhere
    1a:  lock decq 0x0(%rip)
    22:  pop    %rax
    23:  ret
  ```

  The same held of `liss_int_free`, of `liss_list_free`'s element loop and of
  `abolere` itself: uniform, not one inlining accident.
- **Cause.** `free` ends the object's lifetime, so LLVM's dead-store elimination
  removes a store that immediately precedes it. That is correct by the language
  rules — nothing may *legally* observe the result. This store exists precisely
  for the illegal reader, and Rust has no way to say so with a plain assignment.
- **Consequence, and why it is medium and not low.** Spec §5.2 makes the magic
  word the **entire** answer to the live counter's blind spot: an extra free plus
  a missing free nets to zero, and only the magic distinguishes that from a
  balanced program. Without the store, detection depended on the allocator
  handing the block out again first — reliable for a double free an iteration
  apart, and absent for an immediate one. Probabilistic in the small, reliable in
  the large, which is the opposite of what the code's own comment claimed.
- **Fix.** `core::ptr::write_volatile(&raw mut (*h).magic, 0)`. A volatile access
  is an observable side effect no optimiser may remove; it costs one `movl` that
  was always meant to be there. Verified in the rebuilt `runtime.o` on both
  targets — `movl $0x0,(%rdi)` before `call free` on x86_64, `str wzr, [x0]`
  before `bl free` on aarch64 — and confirmed end to end by the mutation that
  found it, which now fails as it should. No new Latin sentence, so the
  catalogue is unchanged.
- **Note.** This does **not** make every redundant free detectable. Codegen
  leaves each slot it frees null (`emissio.rs`'s `libera`), so a duplicated free
  of a *slot* is a no-op by construction. The magic catches a duplicated free of
  a **temporary**, which has no such protection — and that is the case Task 15's
  lists will make easy to write.

### D-29 · the layout proof never reaches the blob

- **Severity:** medium — a compile-time proof that exists, is correct, and
  compares the wrong two things
- **Re-triaged 2026-08-11**, after `097b820` made `abi` a workspace member. The
  repro below no longer reproduces on the command it names: `abi` is compiled by
  any `--workspace` build now, so the `const _` block is evaluated and that build
  *fails*, which is what the entry asked for. **The defect survives with a
  narrower cause**, recorded under **Cause** below: the block proves source
  against source and never sees the blob, so it cannot catch a stale one even
  when it does run. Everything from **Observed** down is the 2026-08-08 record,
  kept as measured.
- **Repro:** reproduced 2026-08-08, against the two-workspace layout. Stage the
  four `.o` blobs from a normal build into `/tmp/horreum/<triple>/`, change
  `crates/runtime/src/dispositio.rs:27` from `pub const ONUS: usize = 24;` to
  `32`, then
  `LISS_RUNTIME_DIR=/tmp/horreum nix develop -c cargo build --workspace --release`.
  On today's tree that build fails at the `const _` block; substitute
  `cargo build -p codegen --release`, which compiles `abi` zero times.
- **Fixed** `9e0b318`, 2026-09-15, by the close at the end of this entry as
  written: `abi` exports `liss_onus` and `liss_verbum`, and `target.rs` reads
  them out of the embedded object. The repro above — staged blobs, `ONUS = 32`,
  `LISS_RUNTIME_DIR` set — now fails `cargo test -p codegen --lib` with `the blob
  says liss_onus is 24 and the compiler emits 32`.
- **Covered by:** `crates/codegen/src/target.rs`,
  `the_blob_s_layout_is_the_compiler_s`.
- **Observed.** The build **succeeds** — 14 s, no warning — and
  `cargo test --release -p codegen --lib` passes **24 of 24**, every
  `target.rs` test among them, against a compiler whose `dispositio` disagrees
  with the runtime blob it embeds by eight bytes.
- **Expected.** A build failure. `crates/abi/src/lib.rs:62-73` is a
  `const _: () = { … }` block holding `ONUS`, `VERBUM` and the three `size_of`s,
  written for exactly this, and its own comment ends "Now something does".
- **Cause, as re-triaged 2026-08-11.** Two causes, and only the second still
  stands on the default path. **(a)** `build.rs:130-145`: when
  `LISS_RUNTIME_DIR` is set, `ex_horreo` copies four `.o` files and `conde`
  never runs. `abi` is a dependency of nothing in the workspace — `grep '\babi\b'
  crates/*/Cargo.toml` finds only its own name and three comments — so a
  crate-scoped `cargo build -p codegen` still evaluates the const block **zero
  times**. Since `097b820` it is a workspace member, so `cargo test` and any
  `--workspace` build do compile it, and there the block runs. **(b)** The block
  compares `abi`'s own `#[repr(C)]` structs against `runtime::dispositio` —
  both read out of *today's source tree*. The blob is bytes from somewhere else.
  A proof that today's source agrees with itself is not a proof that the copied
  object agrees with it, so even on the path where the block runs, a stale blob
  passes. **(b) is why the close below is still the close.** Nothing else holds
  those constants:
  `grep -c "ONUS\|VERBUM\|dispositio" crates/codegen/src/target.rs` is 2,
  both prose. `target.rs` checks the object's *shape* — `e_machine`, defined and
  undefined symbols, that the prelink pulled musl in, `main`'s call order, the
  handler's relocation closure, the CRT epilogues, a size band — and no layout
  constant at all. `build.rs`'s own comment named `target.rs` as "the check"; it
  is corrected in the same commit as this entry.
- **What was measured, against what was assumed.** The claim this entry was
  drafted from was "silent wrong answers and silent leaks, no crash, no failing
  test". **Two of the four hold; two do not, and the difference matters for
  severity.** No crash and no failing test *in the crate whose build script
  chose the blob* — confirmed, 24/24. But the mismatch is not silent at run
  time: `liss run` on a three-element list answers
  `Error: defectus internus: memoria violata est: verificatio`, exit 1, because
  codegen writing elements at `32 + 8i` into an allocation sized for
  `24 + 8i` corrupts the neighbouring header and the magic check catches it. And
  the workspace suite does catch it, loudly: with `--no-fail-fast`, 11
  `conformance` failures, 22 in `series.rs`, 2 in `programs.rs`, 2 in
  `robustness.rs`, 1 in `aemulatio.rs`, plus the catalogue moving two rows to
  `fixtured` because the corruption newly *provokes* two never-covered sentences.

  So the honest statement is narrower than the draft and still worth fixing: **a
  build that must fail succeeds, and the crate that chose the blob cannot tell.**
  Whether a *given* mismatch is caught downstream depends on whether it happens
  to corrupt memory loudly — this one does, and nothing guarantees the next one
  will. A compile-time proof does not depend on that; it is why the block was
  written.
- **The close, and it is cheap.** Export the layout constants as **absolute
  symbols** from the runtime blob — one `#[no_mangle] static` per constant, or a
  `.set` in the staticlib — and add one `target.rs` test reading them out of the
  embedded object and comparing against `runtime::dispositio`. That test can
  see both sides on every build path, `LISS_RUNTIME_DIR` included, which is the
  property the `const _` block cannot have at all: it reads two constants out of
  the same source tree and the blob is not in it. It also turns `build.rs`'s
  "the files are copied, not checked" into a true statement with a named
  exception.

Every claim in §8.1 reproduced. Five carried a wrong number; they are corrected

|----|-----------|---------------------|
| D-01 | `interp.rs:167` | `interp.rs:168` |

**§8.1 has since been corrected** (commit `6f5d6c9`), so the design and this
register now agree; the table above is the record of what was changed and why,
not a live disagreement. Two notes on that correction:

- **D-10.** The design's 116 was not wrong, it was attached to the wrong
  literal: `°C.C.C` does exit 116. That numeral is **10,100**, not 1,000,000 —
  `convert_int_roman` (`roman.rs:212`) splits on `.` and multiplies *pairwise*,
  adding an odd trailing term, so `C·C + C` = 10,100, which `scribe` confirms by
  printing `X̅C`. 10,100 mod 256 = 116. D-10's entry above stays stated against
  `°CCC` → 44, which is the clearer demonstration.
- **D-05.** The corrected §8.1 row records the boundary as lying between 1000
  and 2000, which is what was measured. It was not narrowed further; a
  robustness sweep should treat 2000 as the known-bad point, not as the exact

## Appendix C — corrections to this register, 2026-08-05

Fixing the twenty-two turned up ten places where an entry was wrong about its
own defect. Recorded here rather than silently edited into the entries above,
which stay as the record of what was found. Three of these would have produced
a broken fix if the entry had been followed literally.

**Would have broken something.**

1. **D-14's implied fix destroys two fixtures.** The entry describes the lexer
   consuming greedily "with no backtracking", which invites retreating one
   character at a time until a prefix parses. That turns `°I:I` into `°I`
   followed by a stray `Ident("I")`, silently killing
   `errores/fractio-sine-denominatore` and `roman.rs`'s `fractio sine
   denominatore` with it. Only trailing *separators* may be given back, and
   trimming them needs no retry loop: `parse_roman` splits on `.`, `:` and `/`
   and every leaf reaches `convert_single`, which rejects the empty string — so
   no lexeme ending in a separator can ever parse.

2. **D-05 cites one recursion site; there are three.** `unary()` self-recurses
   on `non` and `-`, and `statement → if_stmt → block → statement` recurses
   through blocks; each aborts independently of the expression ladder. Measured
   before the fix: parentheses clean at 1000 and aborting at 2000, nested `si`
   the same, stacked unary clean at 2000 and aborting at 4000. A counter placed
   only where the entry points would have left two live SIGABRTs for the
   mutation fuzzer to find.

3. **D-22's Expected is unsatisfiable as written.** It asks for the failure to
   be classified into Latin causes including "not valid UTF-8". `UTF-8` carries
   a digit, and rule 4 of the robustness invariant forbids one in any message.
   The cause has to describe the symptom instead — `signis incognitis scripta
   est`.

**Wrong about the code.**

4. **D-11 is a control-flow bug, not two string literals.** Its own Note
   observes that both messages misfire on a nonexistent path; translating the
   literals would have left both misfires in place, in Latin. The fix is a
   `!path.exists()` branch ahead of the extension check.

5. **D-09 does not collide with `programs.rs`.** The entry, and the plan drawn
   from it, treat `type_errors_still_halt_before_any_linting` as pinning D-09's
   behaviour as correct. It asserts only `.is_err()` and passes unchanged. Its
   *name and comment* were wrong, not its assertion; both are corrected.

6. **D-24's `checker.rs:414` is reachable.** `'redde' extra functionem` is
   unreachable from the program pipeline, but `checker::check` walks top-level
   statements with `current_ret == None`, so a top-level `redde` reaches it
   through the legacy API. Since D-19 defers removing that API, the guard
   stays. Only the `check()` copy of the reserved-name rule and the package
   miss are dead.

7. **D-24's table is stale on three rows.** `checker.rs:437`, `interp.rs:321`
   and `:325` are described as "plainly reachable and simply never written",
   but the register's own closing note records fixtures for all three. They
   were wording ambiguities, not coverage gaps.

8. **D-12's "a fix must change both sites" stopped being true.** The two
   `index extra fines` sites were collapsed into one helper before the fix, so
   there was one literal to change.

9. **D-21 cites the wrong guard.** The entry works through `°I:I/N`, `°I:I/`
   and `°I:I/O` and attributes their rejection to the denominator check. It is
   `convert_single` that stops them, with `numerus Romanus vacuus` or `numerus
   Romanus invalidus`; none reaches a division. The conclusion held, the
   mechanism named did not — and that guard has since been deleted as
   unreachable, on evidence: `convert_single` was checked over all 137_256
   strings of length 1..=6 and is never below 1.

10. **D-23's Expected understates what is achievable.** It asks for
    "near-linear time in identifier length". Bounding the split on both the
    longest stem and the longest ending makes it *constant*: 100_000 characters
    went from 24s to 322ms, and 20_000 and 50_000 take the same 318ms, which is
    the process's dictionary-build cost rather than the name.

**One thing that looks like a finding and is not.** `error.rs:20`'s `Monitum in
'{}', linea {}: {}` reads UNCOVERED and always will: `catalogus.rs`'s
`observed_messages` splits each stderr line on the first `": "` and keeps the
tail, so a warning's frame can never be observed. It is an artefact of how the
catalogue observes, not a gap in the corpus. The same is true of the
`main.rs` and `program.rs` sites, which no fixture can provoke because git
cannot carry a file mode — `cli.rs` covers them instead.

### D-30 · A caret under a wide character is one column off per character

- **Severity:** cosmetic
- **Status:** open, accepted
- **Found:** 2026-08-09, writing the caret renderer
- **Where:** `crates/lingua-serpentis/src/fragmentum.rs`

`fragmentum::extract` counts one display column per `char`, and `pictura::depinge` prints the line
and counts the caret from the same character iteration. That is exact for everything a terminal
draws at width 1 — all ASCII, `°`, and every accented letter `is_alphabetic()` admits into an
identifier — and one column short per East Asian or emoji character on the line before the caret.

The fix is `unicode-width`, and spec §11 keeps `lingua-serpentis` at zero third-party dependencies.
A snippet renderer is not the case that earns the exception `libc` earned, so the misalignment is
accepted and recorded here rather than fixed. Nothing is wrong with the *span*: only the count of
columns used to draw under it.

No fixture provokes it — the corpus has no wide characters — which is also why this is recorded
rather than pinned.
